# Build, verify and operate ReadinessOps

For an immediate product review, use the [live-workspace guide](../submission/JUDGE_GUIDE.md).
This page collects the engineering entry points separately from the product tour.

## Local environment

Use Python 3.12 on Linux x86_64 for the pinned analysis environment, and Node.js
with npm for the frontend. From the repository root:

```bash
python3.12 -m venv .venv-analysis
.venv-analysis/bin/python -m pip install --require-hashes -r requirements-analysis-x86_64.lock
npm ci --prefix workbench
```

The repository retains dependency lockfiles. Deployment distribution bundles can
include verified wheels; do not assume those bundles or their prebuilt virtual
environments are present in a fresh public checkout. The separate ARM64 analysis
lockfile describes the corresponding runtime build dependencies.

## Local verification

```bash
PYTHONPATH=src:scripts:tests:. .venv-analysis/bin/python -m unittest discover -s tests -q
npm run build --prefix workbench
```

Local tests use scripted models and synthetic identities where indicated. They
do not replace live AWS acceptance. The latest reassessment repair's targeted
38-test suite and the observed live run are separate pieces of evidence; see
[RO-08](RO08_LIVE_ACCEPTANCE.md).

The frontend render contract in `workbench/test.mjs` consumes a review fixture
generated by `tests/test_workbench.py`. Delivery checks exercise the operator in
an isolated directory with a local AWS CLI double.

## AWS deployment and existing-environment updates

Deployment uses CloudFormation and the repository's versioned, verified artifacts.
Use the relevant runbook for its prerequisites and deployment gates:

| Goal | Documentation |
| --- | --- |
| AWS baseline and deployment prerequisites | [Gate 0 runbook](AWS_G0_RUNBOOK.md) |
| Authenticated workspace | [Workbench runbook](AWS_WORKBENCH_RUNBOOK.md), [business implementation](IMPLEMENTATION.md) |
| Update an existing workspace | [Workspace update and recovery](READINESSOPS_WORKSPACE_UPDATE.md) |
| Optional registered execution connector | [Foundation](AWS_CUSTOMER_FOUNDATION_RUNBOOK.md), [connector](AWS_CUSTOMER_CONNECTOR_RUNBOOK.md), [verified wiring](AWS_CUSTOMER_WIRING_RUNBOOK.md) |

The supplied VendorPayment connector operators require a distinct target AWS
account. The ReadinessOps core works without that connector. A same-account
execution connector has not been implemented or verified by this release.

For an existing environment, use its recorded deployment state and pinned inputs.
The workspace-update runbook explains resume behavior; rebuilding earlier AWS
gates is not a prerequisite for inspecting the live product.

## Source map

- `services/business_analysis/`: Strands assessment and AgentCore runtime entry point.
- `src/authority_delta/business/`: evidence, decisions, actions, outcomes, authority and interchange contracts.
- `workbench/` and `services/workbench/`: frontend source and built assets.
- `services/business/`: authenticated API, queued work, execution gate and recovery.
- `services/customer_publisher/`: registered connector's limited Policy and invocation operations.
- `services/sandbox/`: synthetic target and idempotent acceptance ledger.
- `infra/` and `scripts/`: CloudFormation definitions, build, deployment and verification.
- `evidence/`: observed results and local checks, each with its own declared scope.
